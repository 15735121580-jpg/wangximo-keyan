# Architecture and input contract

The host model calls an MCP tool or CLI. The harness compiles the declared
symbolic task, verifies its ideal readouts, then executes a complete sampled
finite-grid VQE comparison. OpenQuantum supplies the scientific Python SDK.

```text
Codex / Claude Code
        |
        +-- installed Skill: construct and report the declared job
        |
        +-- MCP compile_vqa_job(...) or vqa-joint run
                    |
                    +-- runtime discovery: sdk-access.mjs inspect hamiltonian-simulation
                    |
                    +-- SDK worker: compile -> verify -> train -> select -> fresh terminal
                                        |
                                        +-- strategy, native programs, records and result
```

The MCP server uses its installation interpreter. Scientific execution runs in
a subprocess using the prepared OpenQuantum interpreter. The harness source
is made available to that subprocess through `PYTHONPATH`; OpenQuantum's
reported bootstrap is applied before importing the scientific workflow. The
optional `standalone` backend uses the installation interpreter and requires
the `simulator` extra.

## Job interface

Start from [`examples/three-spin-vqe.json`](../examples/three-spin-vqe.json).
The top-level fields are `task`, `device`, `vqa` and optional `platform`
metadata. The platform label does not add a remote hardware connection.

| Section | Required content |
| --- | --- |
| `task` | `n_qubits`, `initial_bits`, ordered `gates`, and one `observables` entry containing a `label` and nonempty real-coefficient Pauli `terms`. |
| `device` | `n_qubits`, connected undirected `edges`, `native`, `gate_times_us`, `reset_us`, `readout_us`, and `gate_fidelities` with `one_qubit` and `two_qubit` average fidelities. |
| `vqa` | Nonempty `parameter_grid` of binding dictionaries, positive integer `shots_per_term` and `terminal_shots_per_term`, and nonnegative integer `seed`. |

`initial_bits[q]` is the computational-basis bit on logical wire q. A Pauli
word's first character acts on q0. Each Hamiltonian term has `pauli` and
`coeff`. Gate records have `op` and ordered `qubits`; rotations also have
`angle`, and `pauli_rotation` has a local `pauli` word in operand order.

The accepted gate vocabulary is `h`, `s`, `sdg`, `x`, `y`, `z`, `cx`, `cz`,
`swap`, `rx`, `ry`, `rz` and `pauli_rotation`. A Pauli rotation implements
`exp(-i angle P / 2)`. Angles permit finite arithmetic, bound parameter names
and `pi`, using radians. Function calls and attribute access are rejected.
Every parameter-grid binding must supply all names used by the task.

The native basis must contain `rz`, `sx`, `x` and at least one of `cx` or `cz`.
Provide a time in microseconds for each listed native gate. The local
density-matrix execution limit is one through eight physical device qubits;
the original task must fit the device. The topology currently treats links as
undirected. Arbitrary initial states, intermediate measurements, custom
channels, postselection and custom POVMs are outside the compiler interface.

## Compilation and verification

The compiler works before parameter binding. Backward Pauli propagation
identifies gates and wires irrelevant to the declared terminal measurements.
Affine-sector compression expresses reachable basis states in coordinates
generated by the rotation flip masks, transports Pauli readouts and records
their signs. The compiler tries generator and echelon bases, pruning, and
their implemented compositions.

Both original and candidate tasks use the same deterministic native lowering:
breadth-first initial placement, shortest-path routing with restored swaps,
and decomposition into the supplied basis. Candidate admission requires
nonregression against the reference in two-qubit count, instruction count,
depth and allocated sites. Among admitted candidates, the compiler chooses
the lexicographically smallest tuple in that order. These compiler costs
precede the complete-job measurement accounting.

`compilation.json` records considered candidates, admission outcomes, the
selected pass, native programs and the signed readout map. Independently,
Qiskit constructs the original ideal state for every grid point and checks
each original Pauli expectation against its transformed native readout.
Residuals above `1e-9` stop execution.

For a single Pauli's binary outcome, its expectation fixes its ideal outcome
probabilities. This check therefore covers the separately measured Pauli
distributions used by the job. It does not establish joint distributions for
arbitrary measurement settings, arbitrary-input unitary equivalence, noisy
channel equivalence or circuit process fidelity. The rewrite certificate has
the scope of the supplied product input, reachable sector and readouts.

## Sampled controller and physical accounting

Each arm measures every Hamiltonian term at every declared grid point using
`shots_per_term`. It selects the smallest sampled energy, breaking ties by
grid order, then draws a fresh terminal batch at
`terminal_shots_per_term`. Each arm has its own deterministic random stream
derived from the seed. The terminal energy, empirical standard error, selected
binding, ideal energy, modeled noisy energy and raw term records are retained.
Classical diagonalization also supplies a full-space ground-energy reference;
the finite ansatz grid need not reach that reference.

Native gate noise is a local depolarizing channel calibrated to the declared
average one- and two-qubit gate fidelities. It is applied after every native
gate, including basis changes. Reset, readout and memory are ideal. Reported
state fidelity compares each implementation with its own ideal state at that
measurement setting. It is not a logical error rate or process fidelity.

Complete-job totals include the training grid and fresh terminal measurements:
gate count, two-qubit count, peak active qubits, accumulated depth events and
modeled duration. Each hardware shot includes initialization, native
preparation, routing, basis changes and readout. Identity terms produce exact
classical records and consume no hardware shots; requested samples and
hardware shots are recorded separately.

Disjoint gates use an ASAP schedule. Reset and readout are parallel over active
qubits, while shots and measurement settings run serially. `duration_us`
excludes offline compilation and host reasoning; it describes the supplied
execution model rather than measured wall time. Compiler admission does not
guarantee nonregression in these complete-job totals or sampled answer error;
`result.json` reports the observed differences explicitly.

## Reproducibility boundary

`input.json` saves the contract; `compilation.json` and `circuits.json` save the
native choices and per-grid settings. Terminal OpenQASM files include reset,
native preparation, measurement-basis changes and measurement. `result.json`
saves the samples, checks, versions, input hash and workflow hash.
`runtime.json` identifies the selected interpreter and SDK metadata. Replay
with a new output directory and the same runtime; the CLI can replay a saved
`input.json` without editing it.

Search is finite and limited to implemented rewrites and a supplied parameter
grid. One seeded run supports a reproducible observation in a declared noise
model. Global physical optimality, statistical superiority, calibrated
hardware performance and fault-tolerant execution require further evidence.
The stdio MCP interface lets either host use the same local workflow; an
installed host configuration alone does not verify a model-driven session.
